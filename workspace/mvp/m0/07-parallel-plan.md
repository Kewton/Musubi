## 1. まず：🧑 の再分類（2026-09-12）

当初 🧑 が付いていた作業を精査したところ、**大半は「人間にしかできない」ではなかった**。
このリポジトリの M0 でも、H-03（R2バケット・S3キー）／H-07（main保護・Environments）／
H-08（Secrets 6件）／H-05 の予備調査／H-04 の空き調査は、すべて AI が実施している。

**「できない」理由は4種類あり、性質が違う。**

| 種類 | 内容 | 解除できるか |
|---|---|---|
| **① 規則上の禁止** | アカウント新規作成、パスワード・決済情報の入力、送金 | **できない。**能力ではなく規則。権限を渡されても実行しない |
| **② 権限の不在** | 例：API トークンを編集できるトークンが無い | **渡せば解除される** |
| **③ 監督の必要性** | 本番への apply、ロールバックの実演 | **不可逆性の問題。**能力ではない |
| **④ 責任の所在** | 名称、予算、合格の宣言 | **解除できない。**事業判断の当事者は本人 |

この整理に基づき、Issue を「AI ができる準備」と「本人にしかできない一点」に割り直した。

| Issue | 変更 |
|---|---|
| **#21** `wfp_enabled=false` の固定 | 🧑 → **🤖**。サブタスク3つのうち2つは H-13 / #27 で完了済み。残りは Terraform に1行書くだけ |
| **#24** CommandAgent 接点・ピン確定 | 🧑 → **🤖**。`Kewton/CommandAgent`（PUBLIC）への読取アクセスを確認。タグ・SHA の取得は機械作業 |
| **#19** 商標クリアランス | 候補調査と依頼文の作成を **#32（🤖）** へ分離。#19 は**発注（契約・支払い）だけ**に |
| **#20** ドメイン | ゾーン委任・Zone ID 登録・トークン権限追加・結線を **#33（🤖）** へ分離。#20 は**購入（決済）だけ**に |
| **#22 / #23** LINE / Google | **アカウント新規作成と本人確認だけ**が本人。以降は 🧑🤖 として渡せる旨を本文に明記 |
| **#28** CIトークン最小化（M3） | 能力ではなく**権限の不在**。`User API Tokens: Edit` を持つトークンを渡せば 🤖 になる（ただしそのトークンは全トークンを書き換えられる） |

**結果：🤖 が 12件 → 18件、🧑 が 6件 → 4件になった。**

### 本当に削れないのは3つだけ

1. **支払い・契約** — ドメイン購入（#20）、弁理士への発注（#19）
2. **アカウント新規作成と本人確認** — LINE（#22）、Google Cloud（#23）
3. **事業判断の宣言** — 名称の継続可否、M0 合格の判定（#18）

**本人の実作業は合計で1時間を切る。**

## 4.5 検証ゲートを変える Issue は人が入る（2026-09-13 決定）

**ワーカーは `.commandmate/verify.yaml` を編集できない。** CommandMate が `.commandmate/` を
編集範囲から外しており、profile でも緩められない（審判を被審判に書き換えさせないため）。

したがって**ゲートを足す作業は、人（監督側）が `verify.yaml` と `ci.yml` を1コミットで同時に行う。**
ワーカーが `ci.yml` だけを直すと `verify-parity` ゲートが落ちて PR がマージできない。それで正しい。

| Issue | ゲートに足すもの | 分担 |
|---|---|---|
| **#3** | `terraform fmt -check` / `terraform validate` | モジュール本体は 🤖。**ゲート追加だけ 🧑** |
| **#13** | `pnpm infra:sync --env staging --check` | **🧑🤖 に変更。** Issue の中身がゲート追加そのもの |

レーン B から #13 を外したのはこのため。#5 が終わったら、人が #13 を拾う。

## 5. 同時に走らせてはいけない組み合わせ（ファイル衝突）

| 衝突 | 重なるファイル | 対処 |
|---|---|---|
| **#4 × #14 × #21** | `infra/terraform/**`（#14 は `account_id` を `sensitive = true` にするため変数定義に触る。#21 は `wfp_enabled` を触る） | **W2 の3件は直列にする。** 順序は #14 → #21 → #4 |
| **#33 × #4** | `infra/terraform`（`custom_domain_enabled`） | #33 は #20 の購入待ちなので通常ぶつからない。重なったら #4 を先に |
| #13 × #14 | `.github/workflows/`、`.commandmate/verify.yaml` | 波が別（W3 / W2）。同時に動かさない |
| #10 × #25 | `infra/scripts/smoke.ts` | 依存で既に直列。並べ替えない |
| #5 × #6/#8/#9 | 各パッケージの `wrangler.jsonc` | 依存で直列。#5 が形を決めてから各 Worker |

衝突しない安全な組み合わせ：**#2×#7×#24×#32**／**#6×#13**／**#8×#12**／**#10×#11**／**#15×#25**。

> `.commandmate/profiles/musubi.json` の `scope_companions.require` に
> 「`verify.yaml` を触ったら `ci.yml` も触る（逆も）」を入れてある。
> 検証ゲートの定義が2か所で食い違うと「ローカルは通るが CI で落ちる」が起きる。
